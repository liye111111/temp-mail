# SEO/GEO 内容生成目的与流程

本文档用于规范 GetOpenInbox 的长尾关键词内容生产。目标不是简单增加页面数量，而是围绕产品真实能力，持续创建能够回答用户问题、获得搜索引擎收录，并便于生成式 AI 理解和引用的内容。

## 1. 内容生成目的

### 1.1 SEO 目标

- 覆盖与临时邮箱、邮件测试及邮件安全检查相关的长尾搜索需求。
- 建立主题集群，提高核心产品页和工具页的主题权威性。
- 通过指南页、场景页和问题页获得自然搜索流量，并将用户引导至对应功能。
- 用清晰的内链关系帮助搜索引擎发现页面、理解页面层级并传递权重。

### 1.2 GEO 目标

- 让生成式搜索和 AI 助手能够准确理解 GetOpenInbox 的功能、适用场景与限制。
- 对常见问题提供简洁、明确、可独立引用的答案。
- 使用定义、步骤、事实说明、对比表和 FAQ 等易于提取的内容结构。
- 保持产品事实一致，避免生成无法验证的性能、安全或隐私承诺。

### 1.3 产品目标

- 将有明确需求的访问者引导至临时邮箱、邮件查看及邮件安全检查功能。
- 帮助用户理解产品的正确用途、安全边界和数据保存规则。
- 为后续国际化、专题建设和产品功能扩展建立可复用的内容体系。

## 2. 内容原则

1. **以用户问题为中心**：页面首先解决搜索者的问题，然后自然介绍产品功能。
2. **一个页面对应一个主要搜索意图**：近义关键词应合并，避免页面互相竞争。
3. **内容必须与真实能力一致**：不得描述尚未上线的功能，也不得作出“完全匿名”“绝对安全”等承诺。
4. **提供独立价值**：每个页面都应包含针对该主题的解释、步骤、示例、限制或判断标准，不能只替换关键词批量生成相似正文。
5. **安全和合规优先**：不制作鼓励欺诈、绕过平台规则、垃圾邮件或其他滥用行为的内容。
6. **默认面向英语用户**：关键词、URL 和正式页面正文优先使用英语；规划文档可使用中文。
7. **引用权威来源**：名词解释、协议行为、安全建议和时效性事实应尽量链接到 RFC Editor、IETF、标准组织、政府机构或产品官方文档；Wikipedia 可用于通用概念背景，但不替代一手技术规范。

## 3. 内容生成流程

### 步骤 1：建立种子关键词

从已经上线或确定实施的产品能力提取种子词，例如：

- `temporary email`
- `disposable email`
- `receive verification email`
- `temporary email for testing`
- `email header analyzer`
- `SPF checker`
- `DKIM checker`
- `DMARC checker`
- `raw email viewer`

每个种子词必须能够对应到产品功能、目标用户或真实使用场景。

### 步骤 2：使用 Keyword Planner API 扩展关键词

按照 [SEO Keyword Planner API](seo-keyword-planner.md) 的说明，为每个种子词获取关键词建议。鉴权 Token 仅通过本地环境变量提供，不得写入内容文件或提交到 Git。

记录以下信息（以 API 实际返回字段为准）：

- 关键词原文
- 搜索量或需求强度
- 竞争程度
- 建议出价或商业价值指标
- 数据来源和获取日期
- 对应的种子关键词

### 步骤 3：清洗和筛选

删除或降低以下关键词的优先级：

- 与产品能力无关的关键词。
- 带有明显违法、欺诈、骚扰或规避规则意图的关键词。
- 含义不清且无法判断用户需求的关键词。
- 只存在轻微措辞差异、搜索意图完全相同的重复词。
- 产品无法真正满足且没有足够知识支撑的主题。

优先保留同时满足“相关性高、意图明确、可以提供独立价值”的关键词。搜索量不是唯一决策依据。

### 步骤 4：按搜索意图聚类

将关键词合并为主题集群，并为每组指定一个主关键词和若干辅助关键词。

| 搜索意图 | 示例 | 推荐页面类型 |
| --- | --- | --- |
| 工具使用 | `temporary email generator` | 产品或工具落地页 |
| 场景需求 | `temporary email for developers` | 使用场景页 |
| 操作方法 | `how to check email headers` | 教程或 How-to |
| 概念学习 | `what is disposable email` | 指南页 |
| 对比选择 | `temporary email vs email alias` | 对比页 |
| 问题排查 | `why verification email is not arriving` | 故障排查页 |
| 风险判断 | `is temporary email safe` | 安全说明或 FAQ |

如果两个关键词的搜索结果预期和答案结构基本一致，应由同一个页面覆盖。

### 步骤 5：建立内容地图并确定优先级

每个候选页面至少记录：

- 主关键词及辅助关键词
- 搜索意图
- 页面类型
- 英文标题与 URL slug
- 用户要解决的核心问题
- 对应的产品功能和转化入口
- 计划内链到的页面和接收内链的页面
- 内容状态、负责人和更新时间

建议按以下顺序确定优先级：

1. 与已上线核心功能直接相关。
2. 用户需求明确且产品可以直接解决。
3. 能够支持核心产品页或已有主题集群。
4. 有合理搜索需求且竞争强度可接受。
5. 能提供区别于现有页面的独立信息。

### 步骤 6：编写内容 Brief

正式生成正文前，先完成内容 Brief：

- 页面目标和目标读者
- 一句话直接答案
- 主关键词、辅助关键词及相关实体
- 必须回答的问题
- 建议的 H1、H2、H3 结构
- 需要加入的步骤、示例、表格或 FAQ
- 产品功能入口及 CTA
- 必须说明的限制、安全和隐私信息
- 需要引用或核实的事实来源
- 名词解释、协议标准及安全建议对应的权威链接
- 适用的结构化数据类型

### 步骤 7：生成初稿

初稿应遵守以下结构要求：

- Title、H1 和首段清楚表达页面主题，但不堆砌关键词。
- 开头尽快给出问题的直接答案。
- 使用描述性的分级标题，使单个章节可以脱离上下文理解。
- 根据主题加入操作步骤、示例、对比表、注意事项和 FAQ。
- 自然使用主关键词、同义词及相关实体，不设机械的关键词密度指标。
- 只在与当前问题相关时介绍产品，并链接到真实可用的功能。
- 对时效性事实标注来源和核实日期，不虚构数据、评价或引用。
- 技术标准应确认是否已被新 RFC 更新或取代；链接优先使用 RFC Editor 的 `info` 页面，以展示当前状态和勘误入口。
- 结尾给出清晰的下一步，而不是重复全文。

### 步骤 8：SEO/GEO 质量审核

发布前必须检查：

#### 搜索意图与内容质量

- 页面是否完整回答主搜索意图。
- 是否与站内已有页面重复或产生关键词蚕食。
- 是否包含该主题独有的信息，而不是模板化改写。
- 标题与正文是否准确，不使用夸张或误导性表述。

#### 页面 SEO

- Title、meta description、H1 和 canonical 是否正确。
- URL 是否简短、稳定且使用小写英文连字符。
- 是否配置相关内部链接，且锚文本能够说明目标页面。
- 图片是否有恰当的替代文本；页面是否满足移动端和性能要求。
- 页面是否进入 sitemap，并且没有被意外设置为 `noindex`。

#### GEO 与可引用性

- 首段和重要小节是否提供直接、完整的回答。
- 定义、步骤、限制和结论是否有明确上下文。
- 产品名称、功能、保存周期及安全边界是否与项目事实一致。
- 可验证事实是否引用可靠来源，更新时间是否清楚。
- 引用链接是否直接支持相邻论述，是否优先采用原始规范或官方资料。
- FAQ 是否来自真实用户问题，而不是为关键词堆砌而创建。

#### 技术与合规

- 结构化数据必须与页面可见内容一致。
- 外部链接和产品功能入口必须可用。
- 不泄露 Token、Cookie、邮箱内容或其他敏感信息。
- 不包含鼓励滥用临时邮箱的操作指导。

### 步骤 9：发布与内链

发布页面后：

1. 将页面加入相应主题集群、导航或指南索引。
2. 从至少一个相关的已收录页面添加自然内链。
3. 从内容页链接到最相关的功能页，而不是统一指向首页。
4. 更新 sitemap，并验证 canonical、结构化数据和最终 URL。
5. 记录发布日期、目标关键词和初始状态。

### 步骤 10：监测和迭代

定期复盘以下指标：

- 页面是否被抓取和收录。
- 查询词、曝光量、点击量、点击率和平均排名。
- 自然流量、页面参与度及功能入口点击。
- 页面覆盖到的新长尾词。
- 内容是否被生成式搜索或 AI 答案引用；该指标只能作为辅助观察。
- 内容过期、事实变化、链接失效和页面互相竞争情况。

根据真实查询数据补充用户问题、调整标题和章节，或合并表现重复的页面。没有价值的薄页面应改进、合并或下线，不以页面数量作为成功指标。

## 4. 推荐的首批主题

首批内容应在调用 Keyword Planner API 并完成搜索意图验证后确定。可优先评估：

1. What Is a Temporary Email?
2. How Does a Temporary Email Work?
3. Temporary Email for Developers and QA Testing
4. How to Receive a Verification Email Without Using Your Personal Inbox
5. Temporary Email vs Email Alias
6. Is Temporary Email Safe?
7. How to Check SPF, DKIM, and DMARC Results
8. How to Read and Analyze Raw Email Headers
9. Why Verification Emails Don’t Arrive
10. How Long Does a Temporary Email Address Last?

这些标题只是选题假设，不代表可以直接发布。每个主题仍需经过关键词数据、搜索意图、重复度和产品相关性审核。

## 5. 完成标准

一篇内容只有同时满足以下条件才算完成：

- 有明确且唯一的主要搜索意图。
- 内容解决真实问题，并与产品能力一致。
- 已通过事实、安全、SEO、GEO 和重复度检查。
- 已配置元数据、内部链接、canonical 和适用的结构化数据。
- 已加入站点内容体系和监测清单。
- 文档中不包含任何敏感鉴权信息。
