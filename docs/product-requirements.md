# GetOpenInbox 产品需求与实施计划

## 1. 产品概述

GetOpenInbox 是一项面向海外用户的免费临时邮箱服务。用户打开网站后，无需注册账号，即可立即获得一个一次性邮箱地址，并在网页中接收注册邮件、登录验证码和其他短期邮件。

产品价值主张：

> 立即获取免费临时邮箱，无需注册，无需暴露真实邮箱。

产品帮助用户隔离垃圾邮件、营销邮件及潜在的数据泄露风险，但不承诺完全匿名，也不应用于违法、欺诈或规避第三方平台规则的活动。

## 2. 产品目标

### 2.1 核心目标

1. 用户进入首页后，可以在数秒内获得可使用的临时邮箱地址。
2. 用户无需注册、登录或提供个人资料。
3. 新邮件能够自动出现在收件箱中，并清晰展示验证码、发件人、主题和正文。
4. 主品牌域名与临时收件域名分离，保护 `getopeninbox.com` 的品牌及邮件信誉。
5. 服务具备基本的安全、隐私、反滥用和可观测能力。

### 2.2 MVP 成功指标

- 首页到生成邮箱的成功率不低于 99%。
- 正常邮件从 SMTP 接收到网页展示的中位延迟不超过 5 秒。
- 核心页面在移动端和桌面端均可正常使用。
- 用户无需阅读说明即可完成复制地址和查看邮件的操作。
- 系统能够限制明显的自动化滥用和超大邮件攻击。

### 2.3 非目标

MVP 阶段暂不提供：

- 永久邮箱和长期邮件存储。
- 用户账号、密码及跨设备同步。
- 主动发送邮件或回复邮件。
- 邮件转发到用户真实邮箱。
- 自定义域名接入。
- 对所有第三方网站接受临时邮箱的保证。

## 3. 目标用户与使用场景

### 3.1 目标用户

- 希望避免真实邮箱收到营销邮件的普通用户。
- 需要临时接收注册确认邮件或登录验证码的用户。
- 测试注册、通知和邮件发送流程的开发者与 QA 人员。

### 3.2 核心使用场景

1. 用户访问 `getopeninbox.com`。
2. 系统自动创建随机临时邮箱地址。
3. 用户复制地址并粘贴到第三方网站。
4. 第三方网站发送验证邮件。
5. GetOpenInbox 自动刷新收件箱并提示新邮件。
6. 用户打开邮件、复制验证码或点击确认链接。
7. 邮箱及邮件在有效期结束后自动删除。

## 4. MVP 功能范围

### 4.1 首页与邮箱生成

- 进入页面时自动生成随机邮箱地址。
- 提供一键复制按钮及复制成功反馈。
- 显示邮箱剩余有效时间。
- 支持重新生成邮箱。
- 支持在可控规则下修改邮箱前缀。
- 明确说明邮件会自动删除且不可恢复。

### 4.2 临时收件箱

- 实时或短轮询刷新邮件列表。
- 展示发件人、主题、接收时间及是否已读。
- 新邮件到达时提供页面内提示。
- 空状态说明用户下一步操作。
- 支持手动刷新和删除邮件。

### 4.3 邮件阅读

- 展示纯文本和经过安全净化的 HTML 邮件。
- 突出显示常见的数字验证码。
- 提供复制验证码、复制链接等快捷操作。
- 默认阻止远程图片加载，减少跟踪风险。
- 附件在 MVP 中默认不开放；如开放，必须限制类型、大小并进行恶意文件扫描。

### 4.4 生命周期

- 每个邮箱设置明确有效期，MVP 建议为 10 分钟。
- 用户可在页面内延长一次或重新生成。
- 到期后删除邮箱会话、邮件正文和相关临时数据。
- 前端清楚展示倒计时和过期状态。

### 4.5 国际化与基础页面

- MVP 默认界面语言为英语。
- 产品结构预留国际化能力，后续增加简体中文等语言。
- 提供 Privacy Policy、Terms of Service、Acceptable Use Policy 和 Contact 页面。
- 页面明确说明服务边界、数据保存周期和禁止用途。

## 5. 域名与邮件架构

### 5.1 域名分工

- `getopeninbox.com`：官网、品牌、API 和系统通知，不作为公开临时邮箱后缀。
- 独立收件域名池：用于生成临时邮箱，可按信誉和可用性轮换。
- 推荐子域名：`api.getopeninbox.com`、`status.getopeninbox.com`。

### 5.2 邮件接收链路

```text
外部邮件服务器
  -> 收件域名 MX（Cloudflare Email Routing）
  -> Catch-all Email Worker
  -> 校验收件地址是否存在且有效
  -> R2 保存邮件原文
  -> Queue 异步解析与安全净化
  -> D1 保存邮箱及邮件元数据
  -> Workers API
  -> 用户浏览器收件箱
```

### 5.3 地址生成原则

- 使用密码学安全随机源生成不可预测的地址标识。
- 避免连续 ID、时间戳或容易枚举的短地址。
- 地址只绑定当前匿名会话，不依赖用户 IP 作为唯一凭据。
- 客户端会话令牌不得直接暴露内部存储主键。

### 5.4 Cloudflare 部署方案

MVP 采用 Cloudflare Serverless 技术栈，避免自行维护 Web 服务器、SMTP 服务和数据库实例。

| 能力 | Cloudflare 产品 | 用途 |
| --- | --- | --- |
| Web 前端 | Workers Static Assets | 托管响应式前端和静态资源 |
| HTTP API | Workers | 邮箱创建、邮件查询、删除和会话校验 |
| 入站邮件 | Email Routing | 接收独立收件域名的 SMTP 邮件 |
| 邮件入口 | Email Workers | 处理 Catch-all 邮件、验证收件地址并写入存储 |
| 结构化数据 | D1 | 保存邮箱、匿名会话、邮件元数据和过期时间 |
| 对象存储 | R2 | 保存邮件原文、净化后的正文及受控附件 |
| 异步处理 | Queues | 触发 MIME 解析、HTML 净化和元数据提取 |
| 定时任务 | Cron Triggers | 删除过期邮箱、邮件记录和 R2 对象 |
| 实时能力 | 短轮询；后续 Durable Objects | MVP 查询新邮件，后续支持 WebSocket/SSE |
| 人机验证 | Turnstile | 在异常流量下保护邮箱创建接口 |
| 网络与安全 | Cloudflare DNS、TLS、WAF | DNS、HTTPS、基础防护和限流 |

部署原则：

- `getopeninbox.com` 仅部署官网、API 和系统页面，不配置为公开临时邮箱 Catch-all 域名。
- 每个临时收件域名作为独立 Cloudflare Zone 接入，并启用 Email Routing。
- Catch-all 规则只指向指定 Email Worker，不为每个临时地址创建单独的路由规则。
- Email Worker 必须先查询 D1，未知、伪造或已过期的收件地址直接拒绝或丢弃。
- Email Worker 只完成校验、持久化和入队等快速工作，复杂 MIME 解析放到 Queue Consumer 中。
- 邮件原文先以流式方式写入 R2，避免在 Worker 内存中完整缓冲大邮件。
- MVP 前端每 2 至 5 秒短轮询邮件列表；达到规模后再评估 Durable Objects 和 WebSocket。
- 生产环境采用 Workers Paid 计划，避免免费计划较低的 CPU 时间影响 MIME 处理。

### 5.5 平台限制与应用边界

- 普通 HTTP Worker 不能监听入站 SMTP，必须使用 Cloudflare Email Routing 和 Email Workers。
- 使用 Email Routing 的域名必须托管在 Cloudflare DNS。
- Cloudflare Email Routing 当前入站邮件上限为 25 MiB；GetOpenInbox 的 MVP 应设置更严格的 5 MiB 应用上限。
- MVP 默认不开放附件。后续开放时，必须增加扩展名、MIME、大小限制和恶意文件扫描。
- Workers Free 计划的 CPU 时间不适合复杂邮件解析，生产环境应使用 Paid 计划。
- Cloudflare 方案适合 MVP 和早期增长；如果未来需要精细控制 SMTP 响应、灰名单、自定义垃圾邮件策略或更深入的投递诊断，应重新评估专用邮件接收基础设施。
- 平台限制和价格可能变化，上线前须再次核对 Cloudflare 官方文档。

## 6. 安全、隐私与反滥用

- 全站使用 HTTPS，并配置合理的安全响应头。
- HTML 邮件必须经过净化，禁止脚本、表单和危险 URL 协议。
- 默认代理或阻止远程资源，避免打开邮件即触发跟踪像素。
- 限制单封邮件大小、每个邮箱邮件数量和单位时间创建次数。
- 对 API、邮箱生成和邮件读取实施速率限制。
- Email Worker 校验收件地址，只接收仍在有效期内的随机邮箱。
- 应用层限制单封邮件为 5 MiB，超限邮件直接拒绝或丢弃。
- 不建立可公开枚举的邮箱目录。
- 日志中避免记录完整邮件正文、验证码和不必要的个人数据。
- 到期数据应通过后台清理任务及时删除。
- 提供举报和域名滥用处理渠道。
- 明确禁止钓鱼、欺诈、骚扰、垃圾邮件及规避执法等用途。

## 7. 非功能要求

### 7.1 性能

- 首页核心内容应快速加载，并尽量减少阻塞资源。
- 邮件列表接口在正常负载下目标响应时间低于 500 ms。
- 邮件正文按需加载，不在列表接口返回完整内容。

### 7.2 可用性

- 邮件接收服务和 Web 服务可独立扩容与部署。
- 关键队列和清理任务需要失败重试机制。
- 域名、SMTP、存储和 API 应配置健康检查与告警。

### 7.3 可观测性

- 记录邮件接收成功率、解析失败率和端到端延迟。
- 监控邮箱创建量、活跃会话、API 错误率和限流事件。
- 监控磁盘、队列堆积、数据库容量及清理任务状态。
- 不在分析系统中采集邮件正文或验证码。

## 8. 实施步骤

### 阶段 1：需求确认与基础设计

1. 确定 MVP 邮箱有效期、单封邮件大小和单邮箱邮件数量上限。
2. 确定第一批独立收件域名及轮换策略。
3. 确认 Cloudflare Workers Paid、Email Routing、D1、R2、Queues 和 Cron Triggers 的资源配置。
4. 设计匿名会话、邮箱、邮件和域名的数据模型。
5. 完成首页、收件箱和邮件详情页的低保真交互稿。

交付物：技术方案、数据模型、接口草案和页面流程。

### 阶段 2：邮件接收基础设施

1. 将独立收件域名接入 Cloudflare DNS。
2. 启用 Email Routing，由 Cloudflare 配置或确认 MX、SPF 和 DKIM 记录。
3. 建立 Catch-all 规则并指向 Email Worker。
4. 在 Email Worker 中校验 D1 邮箱记录，拒绝未知和过期地址。
5. 将邮件原文流式写入 R2，并向 Queue 投递对象键和处理任务。
6. 在 Queue Consumer 中实现 MIME 解析、字符集转换及正文提取。
7. 实现 HTML 净化、5 MiB 应用限制和危险内容过滤。
8. 将邮件元数据和过期时间写入 D1。
9. 使用 Cron Triggers 建立过期数据清理任务，并为队列配置失败重试和死信处理。

交付物：可以稳定接收、解析并自动删除测试邮件的后端链路。

### 阶段 3：API 与匿名会话

1. 实现创建邮箱、查询邮箱状态和延长有效期接口。
2. 实现邮件列表、邮件详情和删除接口。
3. 实现安全的匿名会话令牌。
4. 增加 API 速率限制、输入校验和错误响应规范。
5. 通过 2 至 5 秒短轮询实现新邮件通知，并保留升级至 Durable Objects/WebSocket 的接口边界。

交付物：具备自动化测试的 MVP API。

### 阶段 4：Web 前端

1. 实现响应式首页和自动邮箱生成流程。
2. 实现复制地址、刷新、倒计时和更换邮箱功能。
3. 实现邮件列表、空状态、新邮件提示及邮件详情。
4. 实现验证码识别和一键复制。
5. 完成 SEO 元数据、社交分享信息及基础国际化结构。
6. 添加隐私、条款和可接受使用政策页面。

交付物：可在移动端和桌面端完整使用的 Web MVP。

### 阶段 5：测试与安全加固

1. 测试常见邮件服务商发送的纯文本、HTML、验证码及多语言邮件。
2. 测试超大邮件、畸形 MIME、恶意 HTML、跟踪像素和危险附件。
3. 测试并发创建邮箱、邮件洪泛、地址枚举和接口限流。
4. 验证过期数据删除、日志脱敏和备份策略。
5. 完成跨浏览器、移动端、无障碍和基础性能测试。

交付物：测试报告、安全检查清单和上线候选版本。

### 阶段 6：上线与运营

1. 使用 Workers Paid 部署生产环境，并启用 HTTPS、DNSSEC、WAF、监控和告警。
2. 小流量开放服务，观察邮件延迟、错误率和资源消耗。
3. 建立收件域名信誉与黑名单监控。
4. 根据实际滥用情况调整频率、容量及邮件大小限制。
5. 发布状态页、反馈入口和滥用举报渠道。

交付物：正式上线的 MVP、监控面板和运行手册。

## 9. MVP 验收标准

- 新访客无需注册即可自动获得临时邮箱。
- 邮箱地址可以一键复制，并显示明确的有效期。
- 外部邮件可以在目标延迟内出现在收件箱中。
- 用户可以阅读纯文本及安全净化后的 HTML 邮件。
- 常见数字验证码可以被识别和复制。
- 邮箱过期后无法继续读取，相关数据按策略自动删除。
- 主品牌域名未被用作公开临时邮箱后缀。
- 创建、收件和读取接口具备限流与基础滥用防护。
- 隐私政策、使用条款和可接受使用政策可以公开访问。
- 邮件接收、API 错误和清理任务具备监控与告警。

## 10. 后续迭代方向

- 多收件域名自动轮换和健康评分。
- 自定义邮箱有效期和邮箱前缀。
- 用户主动选择收件域名。
- PWA、浏览器扩展和移动端快捷入口。
- 开发者测试 API。
- 付费版无广告体验、更长保存时间和私有收件域名。
- 在完成安全评估后支持受限附件预览。
