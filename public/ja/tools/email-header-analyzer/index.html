メールヘッダー解析（オンライン）— SPF・DKIM・DMARCと生ソース

ブラウザーでヘッダーを貼り付けるか、一時受信箱でテストメールを受信。SPF・DKIM・DMARCと生ソースを確認。pass ≠ 安全。

更新日 2026-11-27

GetOpenInboxのオンラインメールヘッダー解析には2つの経路があります。ブラウザーでヘッダーを貼り付けるか、一時受信箱でテストメールを受信して認証と生ソースを確認します。貼り付け解析は既定でローカル処理し、ヘッダーをアップロードしません。受信箱に届いたあと、RFC 5322形式の生ソース、報告されたSPF・DKIM・DMARC、よくある送信者・リンク・添付ファイル名の警告を確認できます。認証結果がpassでも、メールが安全であることの証明にはなりません。

上のツールでヘッダーを貼り付けるか、新規配信のテストメールを調べたいときは一時受信箱を作成してください。

貼り付けヘッダーの解析手順

  1. Gmail、Outlook、その他クライアントからヘッダー全体（または「メッセージのソースを表示」）をコピーします。
  2. このページの解析欄に貼り付けます。
  3. 解析を選び、差出人フィールド、Authentication-ResultsのSPF/DKIM/DMARC、Receivedチェーン要約を確認します。
  4. pass/failは技術信号として扱い、安全判定にはしないでください。

貼り付け解析はブラウザー内で動作します。可能な限り機密性の低いサンプルを使ってください。

一時受信箱で受信メールを解析する手順

  1. GetOpenInboxを開き、生成された一時アドレスをコピーします。
  2. アプリ、ステージング環境、またはメール提供者から、そのアドレスへテスト／確認メールを送ります。
  3. 受信箱に表示されたらメールを開きます。
  4. そのメールの認証結果とリスク表示を確認します。
  5. 生ソースを開き、配信ヘッダー、Authentication-Results、MIME構造を調べます。

セッションは約10分です。機密性の低いテストデータを使い、期限前に確認を終えてください。切れたら新しい一時受信箱を作り、テストメールを再送してください。

レポートで分かること

信号 見えること 限界
SPF・DKIM・DMARC 受信側が評価したドメインについて、よくある認証チェックの結果 pass/failは安全判定ではない
表示上の送信者と技術上の送信者 表示Fromドメインと技術ドメインの差 配送プロバイダ利用など正当な不一致もあり得る

認証結果は安全の証明ではない

SPF・DKIM・DMARCは送信認可、署名、ドメイン整合について別々の技術的問いに答えます。passは特定チェックの成功であり、善意の証明ではありません。侵害された認証済みアカウントからもフィッシングは届き得ます。failも転送など無害な原因があり得ます。

解釈はSPF・DKIM・DMARCの結果の読み方とメールヘッダー分析の手順を参照してください。

この解析ツールがしないこと

  • 貼り付けヘッダーに対するインターネット上のライブDNS/SPF再照会はしません。貼り付けられたAuthentication-Resultsを読みます。
  • 第三者アカウントのスキャン、メールボックス横断、SMTPポート探査はしません。
  • メールが安全・正当・フィッシング無しであることを保証しません。
  • インシデント対応や完全なフォレンジックの代替にはなりません。

完全なセキュリティ製品ではなく、素早く信号を読む入口として使ってください。

一時受信箱でヘッダー確認する場面

ステージングからの確認メール検査、個人受信箱を晒さずにテスト送信の認証結果を比較する、低リスクなサンプルで生ヘッダーを練習する用途に向きます。銀行・医療・パスワード復旧・機密文書・後で取り戻す必要のあるアカウントには使わないでください。アクティブなセッションにアクセスできる人はメールを読める可能性があります。第三者サイトがアドレスを受け入れる保証もありません。

開発者／QA向けはテスト用一時メールを参照してください。
